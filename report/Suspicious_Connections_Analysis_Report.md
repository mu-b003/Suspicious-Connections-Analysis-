## Abstract

This project demonstrates a Suspicious Connections Analysis conducted in an isolated virtual laboratory using Kali Linux, Ubuntu Server, and Wireshark. The objective was to investigate suspicious network communication by generating HTTP requests, SSH sessions, DNS queries, and TCP connection attempts, then capturing and analyzing the resulting traffic. The investigation focused on identifying unusual communication patterns, failed connections, DNS anomalies, and Indicators of Compromise (IOCs) commonly monitored by Security Operations Center (SOC) analysts.

---

- Analyze HTTP communication.
- Investigate SSH sessions.

# Scenario

A Security Operations Center (SOC) analyst receives an alert regarding unusual communication between two internal hosts. Initial monitoring indicates repeated HTTP requests, multiple SSH connections, DNS lookups, and connection attempts to uncommon ports. The analyst captures the traffic using Wireshark to determine whether the activity is legitimate administration or suspicious behavior.

---

# Investigation Process

## 1. Environment Preparation

Both virtual machines were updated before the investigation. Apache2 and OpenSSH services were verified to ensure that the target services were running correctly.

---

## 2. HTTP Activity

HTTP requests were generated from the Kali Linux machine using **curl**.

A loop of ten consecutive requests simulated automated traffic often observed during scripts, monitoring tools, or reconnaissance activities.

The Apache server successfully responded to every request.

---

## 3. DNS Investigation

Two DNS queries were performed.

### Successful Lookup

- bitpluss.com

### Failed Lookup

- ubunyu.com

The failed lookup returned an **NXDOMAIN** response, demonstrating a potential typosquatting domain that resembles a legitimate website.

---

## 4. SSH Investigation

A successful SSH session was established between Kali Linux and Ubuntu Server.

During the session, the following commands were executed:

- pwd
- ls
- exit

This generated encrypted SSH traffic that later appeared as the dominant protocol in the packet capture.

---

## 5. TCP Connection Investigation

Several ports commonly associated with administration or command-and-control infrastructure were tested.

Ports examined:

- 4444
- 9999
- 21
- 23

All connection attempts returned **Connection Refused**, indicating that no services were listening on those ports.

---

# Packet Capture

Traffic was captured live using Wireshark on the Ubuntu machine.

The packet capture was saved as:

## HTTP Analysis

Filtering with:

```
http
```

revealed repeated GET requests generated by the **curl** User-Agent.

Characteristics observed:

- Automated request pattern
- Regular intervals
- Successful HTTP 200 responses
- Apache default webpage requested repeatedly

---

## SSH Analysis

Filtering with:

```
tcp.port == 22
```

showed:

- TCP handshake
- SSH protocol negotiation
- Key exchange
- Encrypted communication
- Session termination

SSH represented the largest percentage of captured traffic.

---

## DNS Analysis

Filtering with:

```
dns
```

revealed:

Successful DNS queries:

- bitpluss.com

Failed DNS query:

- ubunyu.com

The failed query returned an NXDOMAIN response.

---

## TCP Reset Analysis

Filtering with:

```
tcp.flags.reset == 1
```

identified rejected connection attempts toward:

- Port 4444
- Port 9999
- Port 21
- Port 23

These packets confirmed that no services were available on those ports.

---

## SYN Packet Analysis

Filtering with:

```
tcp.flags.syn == 1 && tcp.flags.ack == 0
```

displayed all new connection attempts initiated during the investigation.

Targeted ports included:

- 22
- 80
- 443
- 21
- 23
- 4444
- 9999

This filter provides a complete timeline of connection establishment attempts.

# Findings

The investigation revealed several behaviors commonly monitored by SOC analysts:

- Repeated HTTP requests generated by automation.
- A successful administrative SSH session.
- A suspicious DNS query that resulted in an NXDOMAIN response.
- Multiple failed TCP connection attempts to sensitive ports.
- Dominant SSH traffic throughout the capture.
- TCP Reset packets documenting rejected services.
- Complete visibility into communication endpoints and network conversations.

# Conclusion

This investigation successfully demonstrated how a SOC analyst can identify and analyze suspicious network communications using Wireshark in an isolated laboratory environment. The analysis provided visibility into HTTP, SSH, DNS, and TCP traffic, allowing the identification of repetitive behavior, failed connection attempts, and suspicious DNS activity.

The project strengthens practical skills in network traffic analysis, packet inspection, incident investigation, IOC identification, and professional security documentation, reflecting common responsibilities within a Security Operations Center (SOC).
